# 汇报生成器 WorklogReporter

现有 AI 周报工具的公认失败点是「**还是免不了要绞尽脑汁地回想你做的事**」—— 它们只有一个空输入框。本插件的输入不是回忆,是**本机既有的事实数据**:按需扫一遍活动日志,把这周真正动过的会话、笔记、文件摆出来给你勾选(每条带出处回链、可手工补录),连同被点名笔记的**正文片段**一起交给模型,直接出一份不用大改就能交的草稿。这是「桌面应用内的插件」相对 SaaS 周报工具的唯一不可替代之处。

需求来自前程无忧 51job 2025-06 的调查:**61% 的人认为写日报/周报是典型形式主义、排名第一**;36% 每天为此花 1–2 小时、14% 超过 2 小时;67% 称其消耗精力导致效率下降。

## 与宿主「活动日志」视图 / 活动回顾 Space 的差别

那边是**看行为**(时间线、原始事件、Muse 触发);这边是**出交付物**(勾选 → 草稿 → 归档 → 与上周 diff)。两者读同一份日志,互不覆盖、互不写入对方的数据。

## 三个视图

| 视图 | 干什么 |
|---|---|
| **汇报草稿** | 周选择器、模板 chips、生成草稿、草稿可直接改、保存/打开文件、素材条数与上次生成时间 |
| **本周素材** | 扫描本周素材、统计行(总行 / 采纳 / 插件心跳 / 其它 / 无法解析)、按日分组的勾选列表(时间 + 事件徽章 + 出处回链)、全选/全不选、手工补录 |
| **历史归档** | 周列表(周号 / 字数 / 生成时间,倒序)、点击打开、与上周对比(新增 / 消失 / 沿用 三栏)|

随包 Space「汇报台」把三者摆成:左列素材 / 主区草稿 + 归档 / 右侧对话。

命令面板:`汇报生成器:打开`、`汇报生成器:生成本周汇报`(扫描 → 默认勾选 → 生成 → 写盘 → 打开草稿一条龙)。笔记里 `/` 斜杠项「本周汇报」把本周报告正文(或模板骨架)插进当前笔记。

## 它是怎么工作的(两段管线,不是一段)

```
用户点「扫描本周素材」
   └─▶ Run A(host 模式):引擎只读 cat 本周 7 天的两处活动日志
            ↓ 模型逐字回抄围栏
        插件**在本地**解析 → 白名单过滤 → 合流进素材档案
   用户勾选 / 取消 / 手工补录
   └─▶ 用户点「生成草稿」
            ├─ 对勾选条目里的 vault 路径,插件自己 readFile 回读正文 → 截断成片段
            └─▶ Run B(纯文本,无工具):素材 + 片段 + 模板 → 草稿 → 写进 Reports/
```

**为什么必须两段**:`note.edit` 只有路径 + 行区间,**没有内容**;把日志原样丢给模型它只能编。日志的作用是给出本周动过的**文件清单**,内容要插件自己回读再一起喂。

解析层显式丢弃 `plugin:` 前缀的一切事件 —— 实测本机真实一周:506 行日志里 **341 行是两个计时器插件的心跳**(67%),不过滤等于把三分之二的 token 烧在心跳上。本插件自己发的事件同样带 `plugin:` 前缀,所以天然被丢掉,不会出现「上周我在写周报」这种自指素材。

## 数据存哪 / 数据流向

- **报告** = `<工作文件夹>/Reports/YYYY-Www.md`,**普通 Markdown 笔记**(刻意不注册自定义文件类型:Amadeus 原生就能编、能双链、能导出)。`Reports/` 是固定 ASCII 子目录名,**永不随语言变**。
- **素材档案** = `<工作文件夹>/.worklog/YYYY-Www.json`(点开头,文件树不显)。里面有你的勾选态、每条备注和手工补录 —— 这是**用户数据**,重扫一条不丢。
- **活动日志**(`~/.forsion/activity/`,dev 为 `~/.forsion-dev/activity/`)**只读**,插件不写、不改、不删,也不动 `~/.forsion` 下的任何其它文件。
- 只有**被你勾选的条目**和对应笔记的正文片段会发往**你已登录的 Forsion 后端**生成草稿。未勾选的内容不上传。除此之外不联系任何第三方服务。
- 片段有硬上限:单篇默认 1200 字符(设置里可改,0–4000),全周合计 12000 字符封顶,超出的按被引用次数降序取前几篇、其余只列路径。**绝不会把整篇笔记塞给模型。**

## 几条防线

- **报告被你手改过就不覆盖**:再次生成时对比正文哈希,不符就问你一句,不确认则另存为 `YYYY-Www-v2.md`。只是在 Amadeus 里打开过(宿主落了块标记)不算改动。只改「素材出处」段也不算 —— 哈希只看正文。
- **素材档案损坏 ≠ 缺席**:JSON 坏了先把原字节备份成 `.worklog/YYYY-Www.corrupt-<时间戳>.json`,**备份写成功之后**才重建空档案,并告诉你备份在哪。绝不静默当没有。
- **日志读不可信就不入库**:无法解析的行超过四成(或围栏为空)时判定读取不可信,**不写素材列表**,给你重试按钮并引导手工补录。宁可空着,也不把可疑数据混进素材。
- **解析失败 ≠ 缺席**:单行解析不了不会拖垮整批,统计行会明明白白写「无法解析 N 行」。
- **零推送、零常驻、零定时器**:一切扫描由你点按钮触发。

## 范围说明(明确不做什么)

- **不做飞书 / 钉钉 / 述职 / 年终 / OKR 复盘模板** —— 首版只有「通用三段式」与「红黄绿灯」两套,其余是 v2。
- **零推送、零常驻、零实时聚合** —— 没有定时器、没有后台轮询、不监听文件变化。
- **不做团队协作、不做分享、不上传未勾选的内容**。
- **不写、不改、不删活动日志**。
- **不承诺回溯 30 天以前的周** —— 活动日志本身只保留 30 天(启动时会 prune),所以能从日志生成的只有近 4 周左右;更早的周只能看已归档的报告,视图里会明确提示。
- **不注册自定义文件类型** —— 报告就是普通 `.md` 笔记。
- **不读日志之外的数据源**(邮件 / 日历 / git / 外部任务系统)。git 素材源是 v2 的事,首版范围已被评审收缩掉。
- **不自动清理素材档案的损坏备份** —— 档案损坏时原字节会备份成 `<工作文件夹>/.worklog/YYYY-Www.corrupt-<时间戳>.json`(每损坏一次一份,不覆盖)。插件**只有读写两个口,宿主没给删除接口**,枚举接口也跳过点开头的目录,所以插件既删不掉也数不出这些备份 —— **需要时请自己在文件管理器里清**(正常情况下一份都不会有)。

## 数据保护(读失败绝不当缺席)

宿主的 `readFile` 在「文件不存在」与「读失败 / 当前没有活动库」两种情况下都回 `null`,插件这一层分不清。素材档案里装的是**用户手工补录**(不是可再生的缓存),所以:

- 某周的素材档案只要被成功读到 / 写下过非空内容,插件就记一条高水位;之后再读回 `null` 一律按**读失败**处理,**放弃这次改动**并提示,绝不用空档案覆盖掉已有素材(宁可丢一次勾选,不丢一条补录)。
- 报告文件同理:素材档案里记着「这个路径我们写过」却读不出内容 = 只可能是读失败,此时**照走手改覆盖防线**(问一句,不确认就另存 `-v2`),不会静默覆盖你手写的那份。
- 草稿框里没保存的内容切周不会丢:切走时留在内存里并给一条提示,切回该周原样接着写;手工补录输入框里没提交的那行,切语言 / 重渲 / 落盘失败都不会被清掉。

## 双语说明

界面中英双语,跟随宿主设置(设置里切语言)。**视图内部靠 `ctx.subscribeLocale` 就地重渲 —— 不重挂也会立刻变成英文。**

**已知缺口(宿主侧,不是插件的偷懒)**:宿主贡献点的标题目前是**单字符串**(`registerCommand.title` / `registerSlashItem.label` / `registerView.title` / `registerSetting.label`),宿主不做运行时重解析 —— 插件注册时取的是**当时**的语言,所以切语言后**命令面板 / 斜杠菜单 / 设置页**这几处标题要**重启才跟上**。这是宿主已记录的缺口;为它做「语言变了就把自己 teardown 重来」会打断正在跑的扫描与已打开的视图,故意不做。

不跟随语言的东西(它们是用户数据或技术标识):活动日志的原始事件名、文件路径 / 会话 id / 行区间、日志尾部文本、手工补录内容、模型产出的报告正文,以及**已落盘报告里的一切(含小节标题)—— 生成时是什么语言就永远是什么语言**。

## 旧宿主兼容

07-18 之后的 ctx 面一律可选链,缺席即优雅降级:

| 缺席的能力 | 降级行为 |
|---|---|
| `ctx.getLocale` / `subscribeLocale` | 回退中文(canonical) |
| `ctx.app.workFolder` | 产物落字面量 `汇报生成器/` |
| `ctx.registerStatusItem` | 不注册状态栏项,其余照常 |
| `ctx.achievements` / `ctx.activity` | 静默跳过埋点 |
| `ctx.notify` | 回退 `ctx.app.notify` |
| `ctx.openView` | 命令提示后安静返回 |

硬依赖只有 `ctx.app.readFile` / `writeFile`(没有它整个数据面不存在)。

## 自检

```bash
node check.mjs        # 契约层:日志行文法 / 四时区周历 / 合流 / diff / 覆盖防线 / XSS / 归档自枚举 / 双语 / 旧宿主
```

真机 UIUX(深浅两档对比度 + 中英切换,在 Forsion-Genesis/desktop 下跑):

```bash
node scripts/plugin-view.e2e.cjs <本插件目录> \
  --expect-views compose,sources,archive \
  --expect-commands worklog-reporter-open,worklog-reporter-generate
```

## 安装

```bash
sh install.sh dev     # → ~/.forsion-dev/plugins/worklog-reporter/
sh install.sh prod    # → ~/.forsion/plugins/worklog-reporter/
```

重开 Forsion 后:命令面板「汇报生成器:打开」,或工作台切到「汇报台」Space。
